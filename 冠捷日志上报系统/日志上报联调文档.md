# UART 日志上报联调说明

## 1. 功能概述
- 待上报的日志放在`/oem/qdreamer/qsound/ulog`。
- 当目录累计日志 ≥ 3 KB，或收到上位机的 0x0119“日志收集”指令时，固件自动打包成 `ulog_pkg_YYYYMMDD_HHMMSS_SEQ.tar.gz`。
- 打包后立即通过串口上传，收到上位机的成功 ACK 后会删除压缩包及对应原始日志。

## 2. 串口协议
- **串口参数**：1500000 baud，8N1，无流控。请不要将同一串口配置为 Linux console。
- **帧结构**：
  - 帧头 `0x90 0x40`，帧尾 `0xFF`。
  - 事件码、长度为小端 `uint16_t`。
  - CRC：Modbus16（多项式 0xA001，初始值 0xFFFF，低位在前）。
- **事件码**：
  | 方向 | 事件码 | 含义 |
  |------|--------|------|
  | 设备→上位机 | 0x0120 | 上传开始，payload = `[4B total_bytes][2B total_chunks]` |
  | 设备→上位机 | 0x0121 | 上传数据，payload = `[2B seq][data]` |
  | 设备→上位机 | 0x0122 | 上传结束，payload 空 |
  | 上位机→设备 | 0x0119 | 日志收集请求（可强制上传） |
- **ACK 规则**：
  - 收到 0x0120/0x0122 后请在 2 秒内回 ACK；固件接受 0x0120/0x0122 或 0x8120/0x8122 两种形式，payload 为 1 字节状态（0x00=成功）。
  - ACK 帧头为 `0x81 0xAB`，CRC 算法同上。
- **多包传输**：每个 START→DATA→END 对应一个压缩包；若还有后续包，设备会继续发送新的 START。上位机按 START/END 边界拆包即可。

## 3. 上位机侧流程
1. **串口连接**：确保与设备串口直接相连，波特率 1500000，串口上不要有其他输出。
2. **命令交互**：需要立即拉日志时发送 0x0119；若只想被动接收，可不下发指令。
3. **数据接收与存储**：
   - 监听帧头 `0x90 0x40`，按帧格式解析。
   - 根据 START 帧的 `total_bytes/total_chunks` 初始化缓冲区；按 `seq` 序号写入数据帧；
   - 收到 END 后关闭当前文件并回 ACK。
4. **ACK 回应**：
   - START/END 均需回 ACK，status=0x00 表示成功。
   - 若解包失败或磁盘写入失败，可回非 0x00，设备会保留日志以便稍后重传。
5. **验收**：
   - 设备端可通过 `logcat | grep "[report]"` 看到 `[report] upload ok`；
   - `/oem/qdreamer/qsound/ulog` 中对应 tar 包被删除表示上传完成。

## 4. 联调步骤示例
1. 设备端运行正式固件（例如 `Qsound_am13e2`），并在 `/oem/qdreamer/qsound/ulog` 中放置几 KB 日志文件。
2. 上位机程序连接串口并开始监听；必要时发送 0x0119 触发上传。
3. 观察串口日志：应依次看到 START→多条 DATA→END，并在每个 START/END 后打印 ACK 状态。若无任何 START，请确认串口连线/波特率；若 START 重复，说明 ACK 未收到。
4. 上传完成后，设备端 `ulog` 目录会清空该压缩包，上位机得到的 tar.gz 可直接解压查看内容。

## 5. 常见问题
| 现象 | 可能原因 | 处理建议 |
|------|-----------|-----------|
| 设备端反复打印 `send active evt=0x0120`、`rc=-5` | 上位机未回 ACK | 检查串口连线、波特率、console 占用；确保上位机程序按协议回 ACK |
| START 收到但 DATA/CRC 错误 | 解析算法或帧对齐问题 | 按帧头/帧尾重建帧，使用 Modbus16 CRC 校验 |
| 一直没有打包 | 日志文件不足 3 KB 且未发送 0x0119 | 写入更多日志或通过 0x0119 强制上传 |
| 上传完成但 tar.gz 仍在设备 | 上位机 ACK 状态非 0x00 或未回 ACK | 检查 ACK 内容，确保 status=0x00 |

如需进一步支持，可将串口通讯日志（含 ACK）或设备端 `[report]` 日志反馈给我们协助分析。
